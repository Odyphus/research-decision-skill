# STEM interdisciplinary domain pack

Support status: the lowest support status among every participating domain. This Preview can use `public_source_decision_support_preview` only when all decision-relevant participating domains have an applicable pack and current qualified sources.

## Real tasks

Translate constructs across disciplines, define interfaces between theory, data, instruments, software and systems, reconcile units and scales, combine evidence, choose ownership for validation, and decide which domain-specific uncertainty blocks the joint claim.

## Qualified expertise and source order

Build a source set per participating domain. At least one qualified source or controlling authority must cover each decision-critical interface; a prominent generalist does not replace missing domain expertise. Use the source hierarchy inside each participating pack and preserve the least-supported branch.

## Evidence rules

- Name all participating domains and the joint claim.
- Trace every input, transformation, unit, scale, assumption, interface, and validation owner.
- Do not count one cross-disciplinary consortium publication as independent evidence for all components.
- Test whether terms with the same name have different meanings and whether different terms denote the same construct.
- A valid component does not validate the integrated pipeline.

## Common decisions and failure modes

Typical decisions concern the interface that most limits the claim, the discipline whose standard controls, and the smallest end-to-end test. Failures include unit/scale mismatch, construct drift, responsibility gaps, incompatible uncertainty models, double-counted evidence, and validating components but not their integration.
